# Denzic Platform Product Requirements

This registry records owner decisions that govern shared Listener and
Companion product cores. New platform behavior is implemented only after its
owner steering appears here.

| ID | Requirement | Status | Evidence |
| --- | --- | --- | --- |
| PLAT-REQ-001 | Every capability has one canonical JSON contract, generated Rust/C/TypeScript bindings as applicable, a host Rust layer, and an OS-free embedded C layer with explicit tests. Hardware, OS, storage, timer, GATT-stack, GPIO, LED, and product UI effects remain in product adapters. | active | `capabilities.json`; `tools/verify.ps1` |
| PLAT-REQ-002 | Product repositories consume Denzic Platform through a pinned `third_party/denzic-platform` submodule. A shared decision engine must not be reimplemented as a product-private state machine. | active | Companion `COMP-REQ-035`; product submodule pins |
| PLAT-REQ-003 | Complete the current platformization batch in this owner-selected order: (1) adapt Listener Volcengine SAUC streaming ASR to `StreamingAsrProvider` / `StreamingAsrSession` / `AsrEventSink`; (2) migrate Listener host capture to `host_audio::CaptureSession` while preserving liveness watchdog, macOS pause-before-drop, and permission classification; (3) extract boot safety, startup self-test aggregation, and runtime health decisions as `device_health`; (4) extract battery modeling, charge-full debounce, notification policy, and the standard Battery Service `0x180F` contract as `battery`; (5) extract blocker and idle/shutdown decisions as `power_policy`. | active, ordered batch accepted 2026-07-24 | Platform verification plus Listener-Type, Listener-Firmware, and Companion-Type validation commands |
| PLAT-REQ-004 | `device_health`, `battery`, and `power_policy` expose pure deterministic decisions. ESP reset enums, RTC/no-init persistence, FreeRTOS tasks, watchdog feeding, ADC/NVS, BLE characteristic registration/notification, GPIO wake, light sleep/Stop, shutdown, LED, and logging remain adapter effects. | active | C tests use explicit `CHECK` assertions under Release/NDEBUG |
| PLAT-REQ-005 | The protected Companion-Firmware worktree is not edited or repinned while the owner's e-paper commits and uncommitted changes are in flight. Platform APIs and mirrors may be completed now; Companion-Firmware adoption is a separate pin-and-adapter change after the owner clears that worktree boundary. | active | Repository status and later owner approval |
| PLAT-REQ-006 | Move the owner-approved runtime batch into shared pure decisions: (1) BLE host lifecycle/recovery routing, (2) wake transcript relation, confirmation fallback, and audio-boundary decisions, and (3) observability performance-budget assessment. OS scanning/pairing, BLE stacks, KWS/ASR models, phrase configuration, product thresholds, PCM ownership, firmware/LED/UI effects, and log sinks remain adapters. Preserve Listener 1.0.3 OTA throughput and accepted wake schedules/latency ceilings. Companion adoption remains a separate validated repin under PLAT-REQ-005. A secondary verifier's explicit `Absent` evidence is authoritative over later timeout/unavailable fallback: bare keyword-model acceptance is allowed only before any explicit absence. | active, owner accepted 2026-07-30 | Platform unit tests; Listener session 150 regression; Listener Type/Firmware release gates |
| PLAT-REQ-007 | Add a reusable audio gain governor and paired-level statistics core for Listener and Companion. The OS-free embedded C core consumes product-adapter measurements (pre/post frame mean and peak, speech state, elapsed time and configured noise/gain limits), maintains a bounded noise-floor estimate plus speech hold/attack/release state, and returns a deterministic maximum post-AGC scale and telemetry snapshot. A matching host Rust core replays the same decisions and aggregates paired voiced/noise/gain/limiter percentiles. Microphone/I2S/PDM drivers, DSP/AGC engines, VAD authority, PCM buffers, product thresholds, transport, storage and UI remain adapters. The core must never amplify PCM, must not learn the noise floor from speech, must bound every transition, and must preserve final limiter ownership. Companion adoption is reusable by pin and adapter after PLAT-REQ-005 clears; do not edit its protected firmware worktree now. | active, owner requested 2026-07-31 | Canonical contract and generated bindings; C/Rust parity tests; Listener soft/normal/loud/far/noise paired report; Listener build/WDT/wake regression; later Companion repin and board-specific tuning. |
| PLAT-REQ-008 | Refine the shared wake secondary-confirmation decision so a completed precision-verifier result available within the product budget is consumed before timeout fallback. `Present` accepts, completed `Absent` rejects, and timeout/unavailable may fail open to a primary keyword hit only when no explicit contradictory evidence exists. The shared core does not set KWS thresholds, confirmation budgets, phrase text or model choice. Listener must preserve its accepted sensitive detector and 250 ms budget while rejecting the owner-observed `现在能换吗` and `开始阅读` false wakes for configured `开始录音`; Companion may reuse the same decision with its own phrase and timing adapter. | active, owner requested 2026-07-31 | Shared race/decision tests, Listener real-WAV negative replay, unchanged Listener positive recall/latency gates, later Companion adapter tests. |
